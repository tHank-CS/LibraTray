# LibraTray v1.1.0

LibraTray v1.1.0 为 Yeelight Libra Pro 加入实验性氛围灯左右分区 RGB，并集中修复
Windows 锁屏、屏保、关机和开机自动化。

[English release notes](https://github.com/tHank-CS/LibraTray/blob/v1.1.0/docs/releases/v1.1.0.md)

## 新增

- 仅限精确 `lamp15`、默认关闭的实验性氛围灯左右分区 RGB，包含固件/能力门禁、颜色交换、
  分区预设、受保护的 Windows 自启回放和恢复整灯颜色入口。
- 手动氛围灯自检与恢复：先以 1% 亮度初始化，再恢复此前的电源、亮度和颜色目标。
- 本机独立原子存储最后分区请求与固件风险确认；该记录不随设置导出。
- 新增独立且默认关闭的登录开灯策略，即使没有关机恢复凭据，也可以在 Windows 自启后打开
  主灯和氛围灯。

## 修复

- 快速面板改为按可见内容自适应高度，并在整灯/分区控件变化时保持贴近任务栏，移除本地预设
  下方的大块无用留白。
- 将 Wallpaper Engine/Windows 安全屏保纳入锁定阻止状态，停留在锁屏界面期间不会亮灯，
  实际解锁后只恢复一次。
- 显示器提前亮起、迟到锁定和重复锁定事件不再导致过早恢复或额外关灯。
- 锁定与屏保开始时只写入电源状态，不再在关灯前重发分区颜色、亮度或色温，避免异常闪烁。
- 解锁恢复不再反复重放完整分区预设；现在先有界恢复电源，再在氛围灯开启后补发一次外观请求，
  避免整灯模板与分区颜色反复震荡，并保护主灯恢复。
- 分区预设与开机凭据恢复改用相同的单次有界路径；关闭态预设会保留分区请求，但不会开启任一
  通道。
- 关机时先保存一次性恢复凭据，再只发送必要的电源写入。普通手动启动不会消费凭据；
  现在会在 Windows 首次结束会话请求时预存凭据，避免最终通知缺失而丢失开机恢复
  （[#21](https://github.com/tHank-CS/LibraTray/issues/21)）；若关机时设备实际未熄灭，
  自启会直接清除凭据而不会误亮灯。

## 变更

- 设置 schema 5 在迁移旧配置时会保持新的登录开灯策略关闭；该选项只能在 Windows 自启
  选项下明确启用。
- 调整“Windows 自动化”设置区的标题间距，并将独立登录开灯策略缩进显示为 Windows 自启
  的子选项。

## 重要限制

- 分区颜色是最后请求值，不是设备可读或确认状态；命令成功后仍需目视确认。
- 分区命令的直接证据仅来自一台固件 38 的 YLTD003；其与冷启动渲染器异常之间的因果关系
  仍无法隔离。
- 氛围灯 POST 只是有界运行时恢复，不是固件修复，并且可能短暂以 1% 亮度发光。
- 2026-08-09 的一次冷启动后，设备会在开启氛围灯时缓慢恢复为 `#CC66FF`/50% 整灯模板，
  实体遥控器关开也会复现。LibraTray 可以补发一次分区请求，但无法删除该设备侧模板。
- 本版本产物未签名，Windows 可能显示 SmartScreen 或“未知发布者”警告。

## 验证说明

- 自动化验证覆盖 340 项测试、零警告 Release 构建和 NuGet 漏洞审计。
- 维护者已实机确认分区颜色直接控制、Wallpaper Engine/`Win+L` 联动，以及关机凭据在
  Windows 自启后的条件恢复。
- 修复后的分区预设完整路径、显示器与锁定事件重叠、无凭据独立登录开灯和冷断电 POST
  尚未分别完成专项实机复测；实验功能默认关闭。
