# LibraTray v1.1.0

LibraTray v1.1.0 adds experimental left/right ambient RGB for Yeelight Libra
Pro and a focused set of Windows lock, screensaver, shutdown, and startup
automation fixes.

[简体中文发布说明](https://github.com/tHank-CS/LibraTray/blob/v1.1.0/docs/releases/v1.1.0.zh-CN.md)

## Added

- Default-off experimental left/right ambient RGB for exact `lamp15`, with
  firmware/capability gates, colour swapping, segmented presets, guarded
  Windows-startup replay, and a whole-colour recovery action.
- A manual ambient self-test and recovery action that initializes at 1%
  brightness before restoring the prior power, brightness, and colour target.
- Local-only atomic storage for the last segmented request and firmware-risk
  acknowledgements; this record is excluded from settings exports.
- A separate, default-off sign-in policy that can turn on the main and ambient
  lights after Windows startup even when no shutdown ticket exists.

## Fixed

- Removed the large unused area below local presets by sizing the quick panel
  to its visible content while keeping it anchored above the taskbar.
- Secure Wallpaper Engine/Windows screensavers now participate in lock-state
  blocking, so the light remains off at the lock screen and restores once after
  an actual unlock.
- Display-on, late lock, and duplicate lock events no longer cause premature
  restoration or an extra off operation.
- Lock and screensaver entry now uses power-only writes, preventing segmented
  colour, brightness, or colour-temperature commands from flashing before the
  channels turn off.
- Unlock restoration no longer retries a complete segmented preset sequence.
  It restores power in a bounded stage and applies the requested background
  appearance after power-on once, preventing repeated whole/segment
  oscillation and protecting main-light restoration.
- Segmented presets and startup-ticket restoration use the same bounded,
  no-complete-sequence-replay path. Off-state presets retain the requested zones
  without turning either channel on.
- Shutdown saves its one-time restore ticket before sending only the necessary
  power writes. The ticket is now prepared at the initial Windows end-session
  request so a missing final notification cannot lose startup restoration
  ([#21](https://github.com/tHank-CS/LibraTray/issues/21)). Manual launches
  cannot consume the ticket, and startup clears it without lighting the device
  if shutdown did not actually turn it off.

## Changed

- Settings schema 5 keeps the new sign-in power policy disabled when migrating
  older configurations; it can be enabled only under Windows startup.
- Improved spacing in the Windows automation settings and visually nested the
  independent sign-in power policy under Windows startup.

## Important limitations

- Segment colours are last requested values, not readable or confirmed device
  state. A successful command still requires visual confirmation.
- Direct segment evidence is limited to firmware 38 on one YLTD003. Its
  relationship to the observed cold-start renderer failure remains unresolved.
- The ambient POST is a bounded runtime recovery, not a firmware repair, and
  may briefly emit light at 1% brightness.
- One 2026-08-09 cold-start cycle left the device restoring a slow
  `#CC66FF`/50% whole-background template after ambient power-on, including
  physical remote off/on. LibraTray can reapply the requested segments once,
  but it cannot remove this device-side template.
- The release binaries are unsigned and may trigger Windows SmartScreen or
  an unknown-publisher warning.

## Verification notes

- Automated validation covers 340 tests, a zero-warning Release build, and the
  NuGet vulnerability audit.
- Maintainer hardware checks passed direct segment-colour control,
  Wallpaper Engine/`Win+L` automation, and conditional shutdown-ticket restore
  during Windows startup.
- The corrected complete segmented-preset path, overlapping display/lock
  events, ticket-free sign-in power policy, and cold-power POST have not each
  received a separate final hardware retest; experimental features remain
  disabled by default.
